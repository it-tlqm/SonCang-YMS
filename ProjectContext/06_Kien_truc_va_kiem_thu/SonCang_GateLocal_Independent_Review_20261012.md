## Blocking findings in the supplied SQL

### GLC-01 - P0 - Explicit grants/RLS missing for new tables (and tariff table without RLS)

- `20261012000007_domain_financial_ledger.sql:14-27`: `app_tariffs` is created without `ENABLE ROW LEVEL SECURITY` or restrictive policies.
- Migrations 005-007 create `app_yard_billing_settings`, `app_reefer_power_sessions`, `app_charges`, and `app_payments`, but contain no explicit `REVOKE`/table `GRANT` statements. Migration 004 correctly did so for its own tables.
- Exposure depends on the project's default privileges. Under old Supabase defaults, unintended direct API access may be possible; under opt-in defaults, legitimate reads may fail with 42501. Neither is acceptable as an implicit assumption.
- Fix: explicitly REVOKE client DML on all new domain tables; GRANT required SELECT only to `authenticated`; enable RLS and define narrow policies for every exposed table including tariffs. Keep writes behind audited, permission-checked RPCs. Verify with `has_table_privilege`, `pg_policies`, `pg_class.relrowsecurity`, and `SET ROLE anon/authenticated` negative tests.

### GLC-02 - P0 - Gate ticket has no payable charge

- `20261012000005_gate_ticket_atomic_guard.sql:384-475` creates a priced vehicle visit, but never creates `app_charges` with `charge_type='TICKET'`.
- `20261012000007_domain_financial_ledger.sql:136-316` can collect payment only for an existing `p_charge_id`; none is generated by the gate flow. No other supplied code creates ticket charges.
- Fix: reliably create exactly one ticket charge for each payable vehicle visit in the final migration order (005 before 007), including the 0-to-250000 adjustment path. Ensure a 0-VND exempt ticket is handled separately. Test charge/vehicle payment status reconciliation, duplicate retries, and payment receipts.

### GLC-03 - P0 - Zero-duration reefer `PENDING_REVIEW` can be cleared for exit

- `20261012000006_domain_reefer_power.sql:235-267`: zero-duration unplug transitions to `PENDING_REVIEW` with no charge.
- `20261012000008_domain_exit_clearance.sql:137-148,257-265`: clearance and physical exit check only `power_status='PLUGGED'` and thus do not block `PENDING_REVIEW`.
- RV02 requires zero-duration cases to remain unresolved, never automatically waived. Fix both exit RPCs to block unresolved `PENDING_REVIEW` unless the exact approved resolution process exists; add a regression test.

### GLC-04 - P1 - Reefer payment does not update session status

- `20261012000006_domain_reefer_power.sql:257-267`: auto-generated `app_charges` does not populate `reefer_session_id`.
- `20261012000007_domain_financial_ledger.sql:273-281`: session payment status is updated only if `v_charge.reefer_session_id IS NOT NULL`.
- Fix: set `reefer_session_id` in charge creation, enforce uniqueness per physical session where appropriate, and test that collecting payment changes both charge and reefer-session status.

### GLC-05 - P1 - Missing standalone outbound-vehicle workflow

- `20261012000008_domain_exit_clearance.sql:206-387` exits a container and optionally its outbound vehicle; no supplied RPC exits a truck that drops a container and departs without it.
- This prevents the important scenario: truck A brings container, leaves empty; truck B later arrives empty, collects that same container, and departs. Add a separately permission-checked, audited vehicle-only exit RPC with checks for the associated inbound containers remaining in yard, or document another implemented route, then test the full A/B lifecycle.

### GLC-06 - P1 - Concurrency/idempotency collision handler does not verify full payload

- `20261012000005_gate_ticket_atomic_guard.sql:418-441`: inside `EXCEPTION WHEN unique_violation`, replay only verifies `vehicle_type` and `license_plate`. Driver/contact/ticket note and container payload are not compared.
- The prior normal replay path checks more fields, but the race path may return `is_replay=true` for a different request.
- Fix: share a single full-payload comparison for both paths; test actual simultaneous connections with matching and mismatched payloads (not just sequential calls).

### GLC-07 - P1 - Gate Security can set Dispatch-owned cargo status

- `20261012000005_gate_ticket_atomic_guard.sql:260-277,292-298,447-456`: a caller with `vehicle.visit.create` and `container.visit.create` can submit `p_cargo_status='HANG'` or `RONG` at creation without `cargo_status.update`.
- The V5 separation grants the cargo update to Dispatch. Fix by defaulting to `CHUA_XAC_DINH` for Security and requiring the relevant V5 permission for any other initial status, or documenting a separately approved intake policy.

### GLC-08 - P1 - Tariff AP10 controls remain incomplete

- Fee calculations are still hardcoded (`250000` for tractor-with-container, `100000` per reefer hour, `100000` per storage night) and don't resolve an approved effective tariff version.
- The new `app_tariffs` table has version uniqueness but no approved mutation workflow or no-overlap validation in the supplied files. Its current creation also lacks RLS.
- Fix the access controls immediately. For configurable tariff application, implement an approved tariff-snapshot mechanism with Four-Eyes rather than bypassing AP10. If planned later, keep fee-changing functions blocked in REAL mode and mark it explicitly in the handoff.

## Test coverage and evidence gaps

- Test script `gate_local_e2e_verification.sql` contains **five labeled test groups**; it does not open two concurrent PostgreSQL sessions. Therefore it does not prove actual race safety.
- Existing tests do not directly cover the tariff-table privilege matrix, unapproved RLS DML, cross-yard isolation for financial tables, zero-duration `PENDING_REVIEW` exit, a payable gate ticket paid through ledger, reefer payment status synchronization, or truck A leaving empty.
- A script was reportedly reapplied manually during local debugging. Before Cloud push, apply the exact final 005-008 bytes to a **separate disposable/test database** in migration order and repeat the suite. Never reset existing local or Cloud DEV data without separate approval.
- Request original pgTAP logs, exact exit codes, SQL integration output, migration list, final SHA-256 manifest, and a FULL source bundle; the uploaded ZIP contains only 11 files, not the entire Next.js application.
